# Городские тропы — Коломна

Учебный путеводитель: Express, PostgreSQL, Leaflet и интерактивные GLB-модели.

## Запуск

1. Установите зависимости: `npm ci`.
2. Создайте `.env` с `DATABASE_URL` для вашей PostgreSQL и, при необходимости, `PORT=3000`.
3. Для новой базы импортируйте `kolomnabackup.sql`: в нём 18 точек, маршруты и их остановки. Не импортируйте дамп поверх рабочей базы без резервной копии.
4. Запустите `npm start` и откройте `http://localhost:3000`.

`npm run dev` перезапускает сервер при изменениях. Проверки: `npm test` (изолированные данные, облачная БД не используется).

Если в существующей базе старый список мест, `node scripts/import-project-data.js` проверит состав дампа без изменений. `node scripts/import-project-data.js --apply` сохранит текущие шесть таблиц в приватную резервную копию в `.local-backups/` (не попадает в Git), добавит недостающие поля фотографий и заменит данные одной транзакцией. Скрипт напечатает путь копии и команду `--restore` для отката. Перед применением убедитесь, что `DATABASE_URL` указывает на нужную базу.

## 3D-модели

16 моделей хранятся в `artifacts/3d/`. GLB из этой папки необходимы при переносе/развёртывании проекта и не дублируются в `frontend`. Исходные ракурсы для проверки остаются локально; готовые превью WebP включены в репозиторий.

`backend/models.js` связывает места с моделями по названиям, поскольку ID в старых базах отличаются. API `/api/places`, `/api/places/:id` и остановки `/api/routes/:id` возвращают `model_3d`, `model_poster`, `model_label`, `model_bytes`. Старые пути `model1.glb` и т. п. из дампа заменяются при формировании ответа; вручную менять их в БД не нужно.

Кофейня при «Калачной» использует то же здание. У «Кофейни в Посаде» модели нет. Кремль представлен Маринкиной башней с фрагментом стены. Неизвестные названия получают `model_3d: null`.

Express раздаёт только разрешённые GLB через `/media/models/<slug>.glb`. Превью WebP лежат в `frontend/media/model-posters/`; просмотрщик установлен через npm и загружается с `/vendor/model-viewer.min.js` только после нажатия «Открыть 3D». Исходники Blender и вспомогательные файлы не публикуются.

После замены модели перезапустите сервер: версия URL обновляется по содержимому GLB. Чтобы обновить превью из первых ракурсов, выполните `python3 scripts/prepare-model-posters.py` (для этого шага нужен Pillow; для запуска сайта он не требуется).

## Версия для GitHub Pages

`npm run build:pages` создаёт `dist/`: статический сайт с 18 точками и 5 маршрутами из `kolomnabackup.sql`, фотографиями, 16 GLB и готовыми превью. Сборка не подключается к PostgreSQL и не требует `.env`. В неё не попадают сервер, дамп SQL, резервные копии и исходники Blender.

В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**. Workflow `Publish GitHub Pages` после каждого обновления `main` устанавливает зависимости, запускает проверки, собирает и публикует сайт. Его также можно запустить вручную в Actions. Адрес: `https://katyakorr.github.io/kolomna-project/`.

В этой версии данные обновляются при публикации изменений дампа в репозитории; изменения облачной БД сами по себе на Pages не переносятся. Карта, карточки, маршруты и просмотр 3D работают в браузере. Для локальной проверки раздавайте `dist/` статическим HTTP-сервером; пути поддерживают размещение в подпапке `/kolomna-project/`.
